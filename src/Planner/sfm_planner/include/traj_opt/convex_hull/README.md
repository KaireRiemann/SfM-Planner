# State2State Convex-Hull Optimization

This directory implements the continuous-time constraint path used only by
the ordinary State2State corridor optimizer (`ExpTrajOpt`). Exploration and
SE(3) optimization do not use this path.

## Stable route

There is one production route:

1. Solve the real MINCO objective with fast L-BFGS.
2. Convert each degree-seven polynomial piece with one linear convex-hull
   operator.
3. Evaluate the fixed depth-two V2 position/velocity/acceleration functional.
4. Run the continuous polynomial certificate once as a read-only monitor.
5. Evaluate the current nonlinear flatness envelope in shadow mode only.
6. Accept according to the real objective and Fast L-BFGS result.

The previous V1/V2 cost selection and the standalone full-trajectory ALM route
are not runtime choices. The stable Bezier cost always uses the deduplicated
V2 functional. Hard certificate rejection and packed PHR polish remain
available only behind `convex_hull_require_certification`; they are not part
of the fixed stable baseline. `convex_hull_basis` remains configurable:

- `0`: Bezier, with de Casteljau depth two and flatness shadow diagnostics.
- `1`: MINVO, using its native fixed-depth control-point functional.

### Baseline freeze contract

Future performance or certification work must compare against this route
without silently changing it:

- State2State corridor `ExpTrajOpt` only;
- depth-two V2 control-point objective;
- Fast L-BFGS with the stable objective/decision-step/penalty-change stop rule
  (`lbfgs_fast_phase0_guards_en=false`); the raw penalty-weighted gradient is
  not used as a scale-independent Phase-0 gate;
- cross-replan physical warm start only when the piece topology is unchanged;
  cached waypoints are clipped along a convex overlap segment, and the cached
  seed is selected only when real cost improves by 25% while the gradient norm
  and sampled penalty do not increase;
- exact sampled `FlatnessMap` residuals in the real objective;
- one read-only P/V/A continuous-certificate report after the solve;
- read-only nonlinear flatness shadow diagnostics;
- no packed Phase-2 and no certificate-based rejection.

Any experiment that enables hard certification must do so explicitly and
must use a separate timing mode. It is not promoted to the stable route until
its success rate, solution quality, evaluation count, and total optimization
time all pass the frozen baseline on the same goals.

## Real optimization and conservative certification

The flatness path intentionally has two layers, but only the first is part of
the production acceptance contract.

- The primary objective retains the real `FlatnessMap` residuals. These are
  sampled for the genuinely nonlinear thrust/angular terms; they
  are not replaced by a frozen Taylor penalty.
- A post-solve affine-drag envelope is retained for diagnostics and future
  redesign. Its angular control-point test is non-convex and therefore is not
  currently allowed to affect continuous feasibility, generate polish rows,
  or reject a trajectory.

`sampled_feasible` reports only the real residual grid. Shadow-envelope
violations are kept separate so they cannot masquerade as physical sample
violations.

## Polynomial constraints

For position controls `Q_i` and corridor plane `(a,b)`,

```text
g_pos = (a^T Q_i + b) / position_scale <= 0.
```

Velocity, acceleration, and jerk controls are generated by the Bezier
hodograph,

```text
P_i^(r+1) = (n-r) / T * (P_(i+1)^r - P_i^r).
```

The squared norm polynomial is formed in Bernstein form and constrained by

```text
g_r,k = (s_r,k - bound_r^2) / bound_r^2 <= 0.
```

Depth-two de Casteljau subdivision tightens the enclosure while preserving a
fixed topology inside an L-BFGS solve.

For the degree-seven State2State polynomial, endpoint deduplication leaves
`29 + 25 + 21 = 75` position/velocity/acceleration control residuals per
source segment at depth two. The current high-speed configuration disables
the jerk penalty/certificate, so jerk controls do not enter the hot loop.
This is the minimum residual count that preserves the existing separable
depth-two V2 functional exactly.

## Nonlinear flatness shadow model

At a frozen velocity reference, nonlinear drag is represented by

```text
d(v) = J_ref v + b_ref + e_d,   ||e_d|| <= R_d.
```

The conservative force and force-rate models are

```text
f    = a + (d_h / m) (J_ref v + b_ref) + g e_z,
fDot = j + (d_h / m) J_ref a.
```

Tilt, upper/lower thrust and positive force projection are evaluated on the
degree-elevated joint controls. The experimental angular model uses

```text
k_omega (||f x fDot|| + cross_remainder)
    <= omega_budget * projected_force^2,
```

and includes the Taylor-error cross terms. However,
`||f x fDot|| - omega * projected_force^2` is not jointly convex in the
control pair. Testing only matching joint controls is therefore neither a
sound nor a complete continuous certificate. This result is advisory until
it is replaced by a Bernstein-product or rigorously convex bound.

## Experimental polynomial-certificate-triggered polish

The failed P/V/A certificate ranks violated Bernstein/control constraints.
When `convex_hull_require_certification=true`, only the worst `top_k`
physical constraints are packed, with a configured soft cap. The fixed
stable route keeps this flag false and therefore never constructs the pack.
Neither route packs flatness or Taylor trust-region rows.

The polish objective is a PHR augmented Lagrangian whose inner problem is
solved by L-BFGS. Topology is frozen during each inner solve; new oracle
constraints may only be appended between outer iterations. Multipliers can be
reused only when the topology signature matches.

The experimental hard mode accepts only after a fresh continuous polynomial
certificate. The stable mode records the same certificate without gating.

## Gradient path

All constraints are differentiated with respect to the selected leaf
controls. Gradients then pass through:

```text
leaf controls
  -> transpose de Casteljau selection
  -> reverse degree elevation
  -> reverse hodograph (including duration derivatives)
  -> transpose polynomial-to-basis operator
  -> MINCO coefficient/duration adjoint
  -> spatial points and virtual times.
```

No finite differences are used online. The flatness analytic-gradient tests
remain research tests and do not promote the shadow model into the production
acceptance path.

## Runtime configuration

The main planner YAML only selects the representation:

```yaml
convex_hull_en: true
convex_hull_config: "traj_opt/convex_hull/click_real_highspeed.yaml"
```

The referenced profile owns the Bezier/MINVO switch, certificate/polish
settings, and a complete `convex_hull/penalty/penna_*` set. Dense-integral
weights remain under `traj_opt/exp_traj/penna_*` in the main YAML. At startup,
`ExpTrajOpt` selects exactly one set:

```text
convex_hull_en && profile loaded -> convex_hull/penalty/penna_*
otherwise                         -> exp_traj/penna_*
```

This separation is required because the dense objective integrates point
residuals while the convex objective aggregates normalized control-point
residuals. Their numerical weights are independent tuning parameters even
when a profile is initially seeded with the previous stable values.

Subdivision depth is fixed at two in the stable route. The basis switch is
kept because it changes only the linear convex-hull representation.
Profile option `flatness_en`
enables shadow diagnostics and the eight-node real FlatnessMap residual grid;
the P/V/A certificate is a stable-line monitor.
